# Domain docs

This repo uses a single-context layout:

- `CONTEXT.md` at the repo root holds domain terms and their meanings.
- `docs/adr/` holds architecture decision records.

## Before exploring

Read `CONTEXT.md` and ADRs relevant to the task.

If either is absent, proceed silently. The domain-modeling skill creates
these documents when terms or decisions are resolved.

The existing `AGENTS.md` and `ARCHITECTURE.md` remain project references.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, check existing project terminology
before recording a gap for domain-modeling.

## Decision conflicts

If a proposal conflicts with an ADR, identify the ADR and explain why
the decision should be reconsidered.
